## 1. 如何使用和更新

用户自述已学完 GAMES104 并整理了十份笔记。这是学习背景，不代表本工程已经实现相关系统，也不自动代表已经通过原理、源码或面试自测。

三种进度独立记录：

- **理论：** 已学习课程／有笔记 → 按任务复习 → 能结合实例解释并完成自测。
- **参考源码：** 待研读 → 局部核查 → 能说明具体调用链、数据流与简化点。
- **本工程：** 待创建 → 实现中 → 待验收 → 已通过具体场景验证。另标“自研”“第三方集成”或“仅研究”；“仅研究”条目不代表该模块工程实践目标已完成。

初始阶段核对了十份主笔记的路径和标题，本次按议题局部读取了时间步、动画/位移、矩阵、资产、网络、GI 与 GPU 几何相关段落，没有逐段核验全部正文。除已有探针外，“计划验证”仍是候选实验，不是已完成结果；各模块进入开发前确认具体深度与验收。用户已要求所有模块最终都有不同程度工程实践，整体路线图尚待完善。

章节导航采用“主笔记链接＋精确章节标题”。暂不为十份笔记批量新增锚点；后续实际引用的章节需要固定锚点时再单独处理。

**模块章节与候选实验是学习导航，不能直接推导具体类、程序集或 Pass。** 基础设计已有部分用户确认；设计状态单独记录在 architecture.md，不能把设计确认、源码研读和本工程实现合并为同一进度。

来源：[第 04–07 节渲染主笔记][render]。

2026-10-03 已确认：先 Forward，再实际实现 Deferred 对比；此前已选渲染模块目标包括 PBR、基础阴影、IBL、天空盒、HDR/色调映射/FXAA。地形、天空/云、AO、雾等每类先做代表性实验，再按需整合。详细能力拆分、笔记大章覆盖及未决算法见 [渲染路线](plans/rendering-roadmap.md)；这些能力在 V1 或后续扩展中分步实现。

- 入门对应：“1.5 可渲染物体的数据组织”“1.6 可见性裁剪（Visibility Culling）”“15.2 Forward Rendering（前向渲染）”“15.7 串联渲染流程”。
- 后续对应：“第四章：PBR材质系统 — 物理为王”“第六章：阴影技术演进 — 从Shadow Map到Virtual Shadow Map”“第十四章：后处理 — \"美颜相机\"”“15.6 工程挑战：Render Graph / Frame Graph”。
- 环境代码入口：[Sandbox Program.cs](../samples/G104.Sandbox/Program.cs) 的 `OpenGlProbeWindow`。采用 OpenTK 4.9.4 创建临时窗口和 OpenGL 4.3 Core 上下文，清屏、缩放并输出设备/版本；性质为**第三方集成的环境验证**，没有 Mesh、Shader、材质、相机或正式 GPU 资源管理，不能标为渲染器实现。
- 理论对应：当前仅对应渲染笔记中“第一章：渲染基础设施—GPU、网格与裁剪”的图形硬件/GPU 前置认知，以及后续渲染管线必须依赖的可用图形上下文；尚未实现该章的网格/材质/裁剪，也没有进入第十五章的正式渲染管线。
- 验证证据：2026-10-02 用户确认 Debug/Release x64 均能运行并关闭，截图显示 NVIDIA GeForce RTX 5060 Ti、OpenGL 4.3.0、GLSL 4.30、Core Profile=True。助手对两个配置执行 `--no-restore` 构建，均为 0 警告、0 错误；两配置 smoke 实际输出 X64、OpenTK 4.9.4、退出码 0。缩放、Escape/关闭按钮的逐项验证未获得明确反馈；smoke 也没有自动断言架构和版本。本轮纠正了此前过满表述，完整限制见 [阶段复查](reviews/foundation-review-2026-10-02.md)。截图不纳入仓库。
- 接续工作：在已完成的开发基础上，先补全整体路线并审核相应设计，再逐块验证绘制数据、GLSL 和 GPU 资源生命周期；OpenTK 只提供绑定、窗口和数学工具，不替代这些实现。
- 计划验证：相机变换与坐标轴一致；可展示深度或其他中间结果；切换某个 Pass 时能解释画面变化；记录实际帧耗时后再讨论优化。
