# 独立复现与跨设备接续

本页保存未来明确恢复D5后的办法；当前是否安排由 [status.md](../status.md)和 [agent-workflow.md](../agent-workflow.md)决定。2026-10-02用户先因无第二台电脑暂缓设备测试，随后明确将本机新目录克隆、CI配置/验证、第二设备全部暂缓；它们不构成继续本机V1的前置，也没有验证通过。

<a id="reproduction"></a>
## 恢复D5后怎样复现

1. 先明确目标设备/目录及恢复范围，核对当前本机改动已按既有Git流程保存并同步；本地缓存、原始ZIP、日志和快照不会自动带到另一台设备。
2. 用户通过Git Bash/Git GUI把已同步仓库克隆到新目录，不在原工程内叠加仓库、不重建同名工程或逐个加NuGet。私有截图不是复现资源。
3. 新工作区核对真实提交、文件和当前接续点；在VS打开仓库内g104engine/g104engine.slnx。路径盘符可变，仓库相对结构不变。
4. 按global.json的准确SDK和现有项目/双锁文件，由用户在VS处理缺失环境/锁定还原；不安装浮动latest或手改锁文件。
5. 选择Debug/Release x64与G104.Sandbox，依据 [v1-run-and-review.md](v1-run-and-review.md#run-and-verify)先核对构建/原生/GL/音频，再分别记录人工体验、跨设备及失败条件。获授权构建使用明确现有依赖，不把本机PASS当新设备证据。

同步前看实际工作区，不能仅靠origin/main缓存或领先/落后0 0判断服务器/未提交文件。本机保存、提交、推送与换机复现分别记录；CI是D5独立项目，不因普通克隆自动获准配置。

## 同一设备换聊天

同一设备、同一工作区直接从规则和status恢复当前任务，不为聊天新克隆、建工作树或自动启动旧代理。现有自动回归、人工初步体验、源码学习与跨设备是不同进度；按真正运行结果保存新的复现证据。本轮文档改造未执行克隆、还原、CI或第二设备测试。
