## 项目目标与推进方式

- 用户学完 GAMES104、有十份详细笔记，熟悉 C#/Unity，C++ 经验较少；短期服务 Gameplay/游戏客户端求职，长期打磨可扩展的独立 3D 引擎。
- 渲染、动画、物理、粒子、声音、工具链与资产、Gameplay、AI、网络、核心架构、动态 GI 和 GPU 几何都需要不同程度的工程实践与掌握，不能只保留学习记录。各模块不要求达到相同深度，也不承诺复刻全部工业级系统。
- 按掌握程度推进；旧的“2–4 周、每周 10–15 小时”只是历史估算，不再作为当前约束，目前没有新截止日期。
- 关键原理自研，配合合适的第三方库；分别说明自研部分、第三方提供的能力和简化限制，不以调用库代替理解。
- 每块形成可运行、可观察的成果并保留验证与学习记录；按完整 V1 连续开发及少量预览准备方案，具体节奏在开工弹窗审阅，普通内部检查不逐项审批。用户可反馈调整；重大取舍先解释 Piccolo 参考与推荐理由。
- 维护架构文档与图、简短中文注释，以及“代码入口—笔记章节—固定参考版本—采用/简化方案—验证证据”。理论、参考源码研读和本工程实践分别记录，不互相替代。
- 保留有学习价值的 baseline 与改进方案进行对比；具体开关、重置、重载和对比操作尚未选定，不能假定所有方案都可运行中任意切换。

## 版本与里程碑口径：现状澄清，非新排期

2026-10-03 用户暂缓新专题讨论，先询问版本数量与划分依据，随后明确 Deferred/Undo 进入 V1，并统一名称为“基础综合训练场 V1（用于面试展示）”。**完整的跨模块版本表、后续版本编号和总数量尚未定稿。** 前面主要确认各模块的能力目标与实现路线；旧“基础版终点”等记录按原模块目标理解，具体版本归属以当前范围表和明确决定为准。

合并后按以下三层理解；原 M1 不再单列为阶段，它们也不代表三个已定稿的发布版本：

| 层次 | 大致成果 | 当前状态 |
| --- | --- | --- |
| 开发基础 | 工程/SDK/依赖、图形与 Smoke 探针、Git 与文档入口 | D0–D4 已完成，正式引擎功能未开始；D5 仍暂缓 |
| 基础综合训练场 V1（用于面试展示） | 逐步汇合模型/场景、角色物理/动画、交互/NPC、基础画面、粒子/声音和有限编辑工具 | Deferred/Undo 已明确进入；其余版本取舍仍待确认，内部拆成多个可运行、可验收里程碑 |
| 进阶实践与专题 | 各模块扩展实验、数据布局/ECS/调度，以及网络、动态GI、GPU几何等 | 保留实际代码学习目标；部分路线已选、部分范围未定，不能合成一个无边界的“下一版” |

基础综合训练场 V1 是当前单机主线的首个目标版本，用于面试展示；原 M1 的绘制/变换/资源检查已并入 V1 内部工作，后续扩展另行分期。此前“初版仅 FPS/帧耗时”限制最早阶段的观察投入，不表示 V1 后段或后续对比始终只看 FPS；详细测量按相应实验需要加入。

Forward→Deferred 已明确在基础综合训练场 V1 中完成；CPU→GPU 粒子、FSM→BT、网格 A*→NavMesh 等路线仍须明确整体落点，不默认全部挤进 V1。各模块 R/P/G/T/C/J 等编号只是内部工作分块，旧 M1 已并入 V1，Git 分支用于隔离专题开发；这些都不是发布版本。D0–D5 是开发基础阶段，handoff 的决策索引也不是版本数量。

整体划分建议依据可见成果、前置依赖、可学习/验收的改动量和回退边界。例如先形成最小 3D，再形成可移动/跳跃的早期训练场，随后分块加入真实角色动画、交互/NPC及表现/工具；具体顺序仍待共同确认。渲染、玩法和工具可以交错推进，不按笔记章节顺序一章一个版本，也不要求先完成全部渲染。

当前用户进一步提出先收敛基础综合训练场 V1，把进阶内容安排到后续版本。优先讨论其范围并汇总小里程碑；网络等专题的精细设计继续暂缓。正式汇总时再确定版本/里程碑名称、每块入口条件、成果、停止点与验收，不因本段说明新增实施授权。

## 执行分工与授权边界

- 功能实现由助手主写代码，用户学习、调试、验收并讨论；按完整 V1 方案准备连续推进和可运行预览。具体停止/反馈规则随开工弹窗确认，不把长期分工当当前代码授权。
- 用户在 VS 操作安装、工程配置和 NuGet；Git 用 Git Bash／Git GUI。助手负责说明、文档和获授权的核验，不自动安装依赖、创建项目或变更包版本。
- global.json 曾专项委托助手创建并已完成，不扩展为所有环境操作授权。
- 每批 Git 提交/推送须先展示最终范围并取得明确确认，由用户执行；确认框不可见时接受针对该批的明确聊天确认。文档保存不等于 Git 提交或推送。
- 当前获授权工作为 V1 范围/开发方式讨论及文档维护，已完成原 M1 的流程合并；尚不实施功能代码。集中收敛 V1 方案后取得对应实施授权，设计讨论、草案保存和代码实现是不同状态。
