# G104Engine 开发基础计划

本文件是已确认需求、边界与分工的依据；实际完成情况以 [status.md](status.md) 为准。它取代早先聊天中的 C++、双仓及助手自动安装方案。

## 目标与阶段边界

- 用户已学习 GAMES104，熟悉 C#/Unity，C++ 实践较少；主要求职方向为游戏客户端/Gameplay。
- 短期目标是形成能展示、能解释设计的小型项目；长期持续打磨独立 3D 引擎。首个求职版本的参考预算为 2–4 周、每周 10–15 小时，不据此承诺一次实现所有系统。
- 当前阶段只完成目录与维护文档、环境与工程基础、复现验证和 GitHub 同步。窗口/上下文探针属于环境验证，具体引擎功能不在本阶段展开。
- **软件实现架构与细节尚未确定。** 模块划分、类与接口、数据模型、资源管理、更新顺序、线程和渲染管线，在基础阶段完成后的计划中另行讨论并确认。当前的开发基础选择和历史图示不构成这些设计的约束，见 [阶段边界决策](decisions/0002-defer-implementation-architecture.md)。
- 覆盖渲染、动画、物理、粒子、声音、工具链、Gameplay/AI、网络和核心架构；Lumen/Nanite 等列为进阶研究。各模块分别追踪理论、源码和实践，不把目录存在等同于功能完成。

## 文档与学习完成标准

- `plan.md`：需求、分工、范围、阶段验收。
- `status.md`：唯一的动态进度入口；记录实际结果、等待事项、下一步。
- `setup.md`：用户可视化步骤、完成后的助手验证点。
- `architecture.md`：当前仅保留阶段边界和待讨论事项；基础阶段后再根据确认的设计与实际实现补充架构和图表。历史草案归档为非执行依据。
- `learning-map.md`：代码—笔记章节—Piccolo 来源—方案取舍—验证证据。
- `decisions/`：重要决策的理由与边界；不以旧方案覆盖新分工。

源码使用英文标识符和简短中文注释，重点说明职责、原因、生命周期、坐标系和时间步。每项任务结束由助手更新受影响的图表、映射和状态。新对话先读根 `AGENTS.md`、状态和计划，再检查真实 Git/文件状态。
