## 1. 已确认的三个选择

| 选择 | 助手推荐 | 可选的另一条路线 | 当前状态 |
| --- | --- | --- | --- |
| 正式光照管线 | 先 Forward，再实际实现 Deferred 对比 | 基础绘制之后，正式光照直接从 Deferred 开始 | 用户选择推荐路线；另一项未采用 |
| 此前已选渲染模块目标 | PBR、基础阴影、IBL、天空盒、HDR/色调映射/FXAA | 先 PBR 与基础阴影，IBL、天空及后处理另设后续阶段 | 原目标保留；当前 V1 逐项归属以范围文档为准，不要求全部完成才接入玩法 |
| 扩展专题组织 | 每类先做代表性实验，按需整合进训练场 | 最终把这些实验能力全部整合进同一训练场 | 用户选择独立实验、按需整合 |

以上依据用户对三项交互问题的明确答复，不是根据默认推荐推定。确认的是能力范围和推进路线；下面的 R 分块、具体算法、灯光数量、资源格式和性能指标仍需细化。若改变范围，说明影响并讨论。

## 2. 为什么建议这样推进

- Forward 在绘制物体时计算光照，便于从一个对象追踪到像素。Deferred 先将几何/材质信息写入 G-buffer，再进行光照；适合研究多光源和中间数据，但增加缓冲/带宽及透明、抗锯齿处理。两者都可使用 PBR，不能当成“低级画质/高级画质”或断言后者总更快。
- 基础训练场的最终渲染能力与最初进入 Gameplay 的时间是两个问题。建议在已有可观察的场景后交错推进角色、物理、动画与渲染，不要求先完成全部渲染专题。跨模块具体顺序仍由整体路线决定。
- IBL 先使用预计算环境信息，不等于已延后的动态场景 GI；天空盒也不等于完成大气散射。需要分别标记实践与限制。
- 共享网格、CPU 视锥裁剪和 CPU 组织的普通实例化可在基础渲染中逐步学习。三个对象共享一份 Mesh 不自动等于一次 instanced draw；普通实例化也不等于 GPU 自行裁剪、生成间接命令或 Nanite。
- 初期明确 Pass 及其输入输出、资源所有者即可；通用 Render Graph、Shader Graph 和所有渲染效果任意组合不应成为最初绘制的前置条件。

这些取舍依据本地笔记的管线、材质、阴影、后处理章节，以及固定版本 Piccolo 的实际代码；外部补充可参考作者原始教程 [Deferred Shading](https://learnopengl.com/Advanced-Lighting/Deferred-Shading) 和 [PBR Theory](https://learnopengl.com/PBR/Theory)。教程的简化实现与性能描述不替代本工程测量，实际实现前再固定具体引用代码版本。

## 3. 已确认终点的候选拆分

下列 R 编号仅为渲染模块内部的讨论顺序，不是全工程里程碑编号，也不是要求连续完成全部 R 阶段后才做其他模块。

| 讨论块 | 候选实现内容与边界 | 可见成果与验收方向 | 前置/协作 |
| --- | --- | --- | --- |
| R1 绘制与空间 | 顶点/索引、Shader、变换、观察相机、深度、GPU 生命周期；原 M1 工作已并入 V1 内部 | 简单几何形成训练场雏形，遮挡和坐标正确；实例/共享资源按实际接入验收 | 当前开发基础；数学与资源约定 |
| R2 表面与资产数据 | UV、贴图、法线/切线、材质参数、简单不透明/透明路径；不承诺正确解决任意交错透明排序 | 贴图/法线方向正确；可区分颜色贴图与线性数据；观察透明深度和排序限制 | 场景与资产模块；图像/模型解析库另选 |
| R3 直接光与基本阴影 | 简单经典光照实验后过渡到金属度/粗糙度 PBR，方向光与点光；先方向光 Shadow Map 和基本邻域过滤，点光阴影后续单独讨论 | 材质球参数变化可解释；阴影图可查看；观察 bias、分辨率和边缘过滤的影响 | R2；光源与材质数据；深度渲染目标 |
| R4 环境与颜色链 | 天空盒、预计算 IBL、HDR、曝光、tone mapping 及显示颜色输出 | 分别观察直接光与环境贡献；验证粗糙度变化及 HDR 映射，避免重复颜色转换 | R2/R3；环境资产与多 Pass 资源管理 |
| R5 AA、诊断与基本效率 | FXAA；法线/深度/阴影等中间结果；CPU 视锥裁剪、绘制/资源统计，普通实例化对比 | 能解释抗锯齿的收益/模糊代价；裁剪不误删对象；比较可见数、提交数与实际耗时 | 场景包围体、绘制列表、工具诊断 |
| R6 管线对比 | 已明确进入基础综合训练场 V1；按 Forward 先行路线，再构建精简 Deferred/G-buffer 与光照路径，尽量共用场景与材质输入 | 查看 G-buffer；相同场景、相机、光照条件下比较画面与成本；单独说明透明路径 | 已有光照主线和渲染目标管理，不以完成 R4/完整 IBL 为前置；具体方案待设计 |

PBR、IBL 等不是一次性工作。IBL 可先消费预计算贴图支撑场景，再用独立预计算实验研究辐照度、粗糙度预滤波和 BRDF LUT；具体自研范围还需细化。不能把只加载成品纹理写成已经自研完整预计算流程。

此前选定的渲染能力目标保留，但具体 V1 归属及本表拆分仍需收敛；不能因此把点光阴影、Bloom、调色 LUT、自动曝光或高级抗锯齿都默认为同一批任务。

## 4. 扩展章节的代表性实践（候选清单）

这些主题保留实际实验入口。每类选择代表性方案，不自动承诺该章所有子算法；具体最低范围与整体阶段尚待逐项收敛。

| 笔记主题 | 候选代表性实践 | 与基础版的区别 / 后续边界 |
| --- | --- | --- |
| 第 3 章预计算光照 | 消费 Lightmap，或少量 Probe/球谐采样插值实验 | 不自建完整离线烘焙器；观察静态数据面对动态变化的限制 |
| 第 6 章高级阴影 | CSM 或 PCSS 等改进实验，先确定一种 | 不同时承诺所有软阴影/VSM；需要比较质量、覆盖与成本 |
| 第 7–8 章地形 | 高度图网格、材质混合、有限规模 LOD | 普通平面不算地形系统；虚拟纹理和超大世界流送另定深度 |
| 第 9 章天空 | 简化大气散射或 LUT 实验 | 天空盒不替代该实验；解释太阳高度、视线与近似条件 |
| 第 10 章云 | 有限云层、噪声密度与简化体积步进 | 不先建设天气系统；观察密度/步数及采样误差与成本 |
| 第 11 章 AO | 一种屏幕空间 AO 实验 | AO 不等于直接光阴影或完整 GI；展示离屏信息与接触伪影限制 |
| 第 12 章雾 | 先深度/高度雾，体积散射再定范围 | 观察距离/高度与合成关系；不能把简单雾标成完整体积雾 |
| 第 13 章 AA | 基础 FXAA 后，对 MSAA/TAA 等选择对比实验 | 若选 TAA，需要历史、运动信息与重置/拖影验证；不只是加一层模糊 |
| 第 14 章后处理 | Bloom 与 LUT 调色分别形成小实验 | 需实际处理像素，不能只接一个名称为对应效果的 Pass |
| 第 15 章管线 | Deferred 对比、显式 Pass 依赖，之后再评估多光源组织和 Render Graph | Forward 也可提供深度/法线做屏幕效果，不因 AO 就默认必须采用 Deferred |
| 第 16 章前沿 | Shader 管理、复杂材质等按目标选择实践；硬件光追另评估 | 当前 OpenGL 4.3 基线不等于支持所有现代 API/硬件特性；不自动更换图形 API |
| 独立第 21/22 节 | 动态 GI、GPU 几何的可运行简化机制实验 | 按既定后续专题/分支方向推进，不声称复刻 Lumen 或 Nanite |

地形、天空/云、AO、雾等采用用户已选的“每类代表实验、按需整合”方式，不要求全部同时集成到训练场。各实验的具体算法和最低深度仍待确认；未整合的实验也要可运行、可解释、有代码入口及验收，不退回只有阅读记录。

## 5. 自研、集成与掌握证据

- 推荐自研：Shader 与光照计算、空间转换、Pass 组织、资源管理、裁剪/批处理和各代表性实验逻辑。
- 第三方边界：OpenTK 提供窗口与图形 API 绑定；图像/模型格式解析可用库；资产制作或烘焙可用外部工具。具体库/素材及授权使用条件在资产任务中再确认，本轮不选包或安装。
- 每个检查点都保存代码入口、笔记章节、固定参考、采用/简化方案及验证证据；未创建的入口继续标为待创建。
- 验收同时观察画面正确性、参数变化、必要边界情况和资源成本。性能比较固定场景、相机、分辨率和质量条件，记录 CPU/GPU 工作量，不能只凭“算法名字更先进”判断优化成功。
- 角色蒙皮和粒子绘制需要渲染侧接口，但骨骼求值、粒子生命周期分别属于动画/粒子模块；不能把它们从总体路线遗漏，也不在渲染方案中包办全部逻辑。
