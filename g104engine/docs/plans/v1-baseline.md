# 基础综合训练场 V1：批准范围与设计基线

本页合并V1范围讨论与正式实施方案，作为**V1范围和设计取舍**的权威记录。这里区分用户明确选择、助手按授权定案、后来实施校正和未采用候选；实际进展与最新验证由 [status.md](../status.md) 维护，低级接口、参数和操作合同由专题指南维护。统一名称为“基础综合训练场V1”，用途为“面试展示”；旧“面试Demo/面试V1”指同一版本。

<a id="scope"></a>
## 1. 批准范围与排除项

V1目标是可重复演示的第三人称非战斗训练场：移动/跳跃和有限坡台、动作混合、按钮/门/触发区、少量感知/寻路/跟随NPC、粒子/声音反馈、Forward/Deferred对比及有限编辑工具。表现深度服务展示与学习，缩小内容和变体数量，不删去生命周期、失败保护、状态归属等正确性要求。

| 模块 | V1批准的有限范围 | 明确后移或排除 |
|---|---|---|
| 核心/场景 | 对象组件、明确阶段、60Hz模拟/独立显示、主线程同步准备、输入与资源归属、安全重置/重载 | 数据布局、小ECS、并行/自研Job、Fiber、异步加载；组件不是完整ECS |
| 角色/物理 | 自研角色规则＋成熟后端查询/刚体适配；镜头相对移动，平地/墙滑/跳跃/有限坡台 | 平移平台、受控推箱、复杂坡台组合和进阶物理 |
| 相机/输入 | 第三人称跟随/旋转及有限遮挡，编辑环绕观察；游戏/UI输入归属、边沿单次消费 | 多模式镜头、更多设备、完整重映射 |
| 资产/动画 | glTF/GLB受控子集、同骨架in-place素材；Idle/Walk/Run速度混合、跳跃/空中/落地过渡、事件与有限状态配置 | FBX运行导入、重定向/IK/Additive/Root Motion、完整动画图编辑、Cook/流送 |
| 设计数据 | 稳定对象身份、受控父子层级、单层模板/明确覆盖、设计场景保存与安全重载 | 运行存档、完整资产GUID数据库、嵌套/变体Prefab、通用Apply/Revert |
| Gameplay | Sandbox内C#规则与数据配置；有限机关、目标/完成事实、可重置演示 | 战斗、背包、大型任务系统、脚本VM/完整代码热更新 |
| AI | 少量NPC感知/记忆/FSM，巡逻/跟随/搜索/返回，受控平面网格A*及真实角色执行 | 小BT/NavMesh对照、群体/规划/学习型策略；不保证NPC走所有玩家坡台 |
| 渲染 | Forward先行再Deferred实际对照、基础PBR/方向阴影、背景天空、HDR/色调映射/FXAA和中间结果观察 | IBL、点光阴影/CSM、地形/云/AO/雾、TAA、Render Graph/Tiled/Clustered、GI/GPU几何 |
| 粒子/声音 | 有限CPU Burst/Billboard及透明合成；2D/3D一次性/循环、相机Listener、基本播放管理 | GPU粒子、持续Emitter/复杂表示、完整音量优先级/虚拟Voice、传播/混响/流送 |
| 工具/观察 | 有限创建/删除/变换/参数编辑、父子操作、Undo/Redo、Play/Stop保护未保存设计、模块调试和FPS/帧耗时 | 任意操作撤销、通用编辑器/Gizmo/视口拾取、单步、通用反射面板、完整Profiler |

Deferred与有限Undo/Redo明确纳入V1；IBL、平台/推箱明确后移。这些范围回答先于正式开工，不独立构成代码授权。长期全模块不同深度实践目标保留，后移不等于删除。

<a id="design-boundaries"></a>
## 2. 受控设计边界与失败保护

### 工程、时间与状态归属

- 保留Engine/Sandbox两项目：Engine提供通用能力且不依赖Sandbox；Sandbox组织窗口安全点、训练场配置和专属玩法。目录/类名按职责组织，不提前冻结长期拆分。
- 基础主流程由主线程按明确阶段推进，模拟固定60Hz、显示独立；后端可有内部线程，不能据此宣称整个进程单线程。逻辑输入、实际运动/事实、动画及显示各有写入者。
- Move持续状态与Jump/Interact边沿分开，零步/多补步、UI捕获、焦点/暂停和加载后时间按同一合同处理；Look增量不能在补步中重复应用。绘制与Pose显示不得重发逻辑事件。
- 控制器提交角色世界位移，in-place动画消费实际速度/接地事实；NPC产生意图并经控制器执行，相机不改角色位置，表现插值不回写模拟。固定步不保证跨设备逐位确定性。
- 新场景/资源在候选作用域准备成功才提交，失败清理部分创建资源并保留原设计及有效旧状态；不依靠“当前活动场景”猜资源归属。GL创建/上传/绘制/释放遵守有效上下文线程，Jolt全局初始化与场景世界寿命分开，声音与设备资源按所有者清理。
- 退出/初始化失败也必须收敛资源，不仅依赖正常窗口回调或GC。当前具体帧顺序、补步/丢时参数、输入处理和清理路径见 [architecture.md](../architecture.md)。

### 设计场景、模板与运行实例

先保存设计场景，不能序列化整个Runtime。持久对象身份、资产引用和GPU/Jolt/AL运行句柄分开；设计文件有版本/字段/引用校验，不因JSON能解析就视为准备成功。输入资产受控支持，不支持格式/采样器/扩展应可定位拒绝，不静默冒充完整支持。

设计数据与初始资源、用户可写设计路径分开；损坏/缺资源的用户设计保留原件并说明后回落seed，后续保存保护被拒原件。保存临时写成功才替换；失败不破坏原文件/内存。单层模板实例保持独立有效字段与白名单覆盖，不自动传播所有默认值变化；父子树不是嵌套Prefab。

Play使用**当前内存设计，包括未保存编辑**创建可丢弃运行实例。设计DTO与历史保持独立；Stop从保留设计恢复预览并清理运行变化，预览准备失败不丢设计。编辑预览没有独立物理模拟世界，最新碰撞/导航在下一次Play准备，运行存档/将运行修改应用回设计均不在V1。

Undo只覆盖约定设计命令，不能从“有Undo栈”推断任意操作可撤销。事务校验后提交，拖动合并/取消/失败回滚有定义；删除恢复稳定身份/引用，存在未解除外部引用时拒绝子树删除。有效新编辑清Redo，Save更新实际保存基准，跨场景Load清旧历史，Play/Stop保留设计历史；运行位移/动画游标与句柄不入栈。低级字段、命令和Saved/dirty规则见 [scene-and-editor.md](../guides/scene-and-editor.md)。

### 用户确认的受控父子层级（D52）

最初平级建议只为控制首版成本；用户要求解释商业引擎挂接关系与取舍后，明确选择V1受控基础父子层级，平级建议撤回。例如“机关组→门/按钮/灯”可共同变换而各子对象保存相对姿态。场景树、物理约束、Prefab嵌套与模型骨骼树是不同关系。

- 普通对象支持分组/父子挂接、局部/世界变换、层级显示、保存/重载；禁止环、自挂接、无效父ID，换父不改变已有GUID。
- 重挂接默认保持世界姿态，父引用和新局部TRS在同一事务更新；不可逆、缩放限制或不可还原剪切时拒绝，不能悄悄丢失变换信息。采用本工程行向量约定而非照搬其他引擎布局。
- 删除组以整棵子树为一次Undo事务，恢复全部后代身份/局部值/父关系及约定引用；存在外部引用先拒绝并指出来源。重挂接/恢复后刷新后代及显示历史。
- 当前Player/Npc为根节点且单位缩放，体型由参数控制，避免父级/控制器同时写姿态；角色与移动门下仅允许纯显示后代。活动相机/动态刚体作为根节点原则保留，但可编辑DTO没有这两类组件，不能称已提供其挂接编辑。
- 所有带有或将接收可编辑子对象的节点均要求正统一缩放，不只限Group；叶子限制由组件决定。静态对象可分组，运行组保持静态，不能通过父组变换冒充平台能力。
- 导入模型/skin骨骼树内部单独求值，不套用场景编辑限制到全部骨骼节点，也不变成可任意删除的场景对象；逻辑碰撞/导航和后代表现插值分别消费相应变换。

理由来源可选查 [Unity Transform](https://docs.unity3d.com/6000.0/Documentation/Manual/class-Transform.html)、[Unity SetParent](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Transform.SetParent.html)及 [UE SceneComponent](https://dev.epicgames.com/documentation/en-us/unreal-engine/components-in-unreal-engine)。它们的对象模型并不相同，来源不能替代本工程合同或授权。

<a id="design-choices"></a>
## 3. 已选方案、理由及后来校正

| 选择 | 理由、自研/集成与真实边界 |
|---|---|
| Forward→Deferred | 先追踪对象到像素再观察G-buffer；两者共用场景/材质/骨骼/灯光。编辑态选择、下次Play生效，未承诺运行中无缝切换；PBR可用于两管线，Deferred不天然更快 |
| 基础光照与颜色 | 有限方向/点光、仅方向阴影、固定Pass/曝光、Reinhard/FXAA、天空仅背景；IBL与大气不是天空盒附赠能力。低级G-buffer/空间/颜色/透明规则在渲染指南 |
| HDR格式校正 | 初始HDR16F是助手按授权定案的起点；独立BRDF数值验回发现GGX偏置错误，正确粗糙度/强度范围的约194061.8超出half65504，因此改32F、增加8bytes/pixel，保留能量/粗糙度语义。不是用户逐项指定，也不把旧16F理由当现行合同 |
| 资产与动画 | SharpGLTF负责格式读取、StbImageSharp负责解码；项目自研空间/引用/实例/寿命、采样/混合/层级/蒙皮。同骨架非Root Motion素材减少重定向前置，保留根变换，在角色实例边界统一朝向/高度/feet校正 |
| 物理 | 比较绑定、部署、查询和自研边界后采用Jolt；Bepu是未采用备选，其受控查询适配成本也是比较依据，不只因为Piccolo用了Jolt。角色规则自研，后端ray/sweep/精确重叠不等于库控制器，也不证明完整动力学/Joint/Trigger已接入 |
| AI与事实 | FSM/受控平面A*先形成感知→意图→真实执行→失败反馈闭环；门的姿态/碰撞/导航失效同步，事实只发布一次。任务请求、感知记忆、动画状态分别归属；参数重载不是脚本或代码热更新 |
| 工具与历史 | ImGui只提供界面；项目实现OpenTK适配、校验/命令、事务、身份恢复及设计/运行隔离。历史上限等普通参数由助手确定，不伪称用户逐项批准 |
| 粒子与声音 | CPU生命周期先行，粒子排序/合成与模拟分别负责；成熟OpenAL设备后端配合自研PCM/Voice管理。Listener随相机，动画marker与已提交Gameplay事实不能混用为重复声音来源 |
| 离线输入准备 | 已选Ogg离线转PCM16，不引入运行时Ogg库；便携转换工具不是运行依赖。正式范围包含角色/OpenAL/许可部署、便携FFmpeg校验转换和必要复制配置，精确版本/来源/哈希在依赖指南 |

实际支持子集与低级合同：[rendering-and-animation.md](../guides/rendering-and-animation.md)、[physics-and-gameplay.md](../guides/physics-and-gameplay.md)、[scene-and-editor.md](../guides/scene-and-editor.md)、[dependencies.md](../guides/dependencies.md)。原实现的half/排序/UV覆盖/共享skin-rigid、编辑事务/Saved、导航边界/半径/NPC朝向及后续TRS/UI修复属于同范围校正；分别保留日期和证据在评审记录，不将某次验证推为全部输入无缺陷。

## 4. 最小3D里程碑合入V1的决定

| 原M1内容 | 合并后的用途 |

## 6. 成果、验收与学习的口径

成果要能运行、重置并观察跨模块行为；学习要能解释数据流、取舍、限制并完成调试/小改动。用户首轮体验、助手自动验证、源码掌握和专项/跨设备覆盖分别记录，不能相互替代，也不因未穷尽所有分支要求无故重新整轮验收。

验证围绕实际行为：数学/时间/输入、身份/层级/历史/路径、真实Jolt/Gameplay、素材/WAV解析、GPU/原生UI/OpenAL、尺寸/清理/连续重置与准备失败分别留证。`--smoke`只说明环境，`--verify`包含真实原生要求，图形/音频另有专项；现行命令及成功判据在 [v1-run-and-review.md](../guides/v1-run-and-review.md)。V1历史Debug/Release采用既有依赖和`--no-restore`并记录bin/obj，不把本次文档改造当功能重跑。

可选演示约3–5分钟：走跑/跳跃→机关/目标→NPC绕路跟随/搜索→声音粒子→状态观察→重置。时长、关卡流程、录像/展示脚本只是建议，录制/打包上传另按需求。值得解释的三链路为输入→真实运动→动画相机，感知→路径→实际执行/失败，设计/资产→运行事实→重置/释放。已有运行说明、架构与代码笔记映射是材料，求职建议来源不是招聘保证。

<a id="version-continuation"></a>
