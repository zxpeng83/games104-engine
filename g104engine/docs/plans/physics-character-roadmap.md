本页维护自研/后端分工、角色的分期目标与物理原理/进阶实践。V1有限范围在[v1-baseline.md](v1-baseline.md#scope)，平台/推箱和候选实验须另行收敛。

现行查询/角色入口及后端边界见[physics-and-gameplay.md](../guides/physics-and-gameplay.md)，代码与笔记见[learning-map.md](../learning-map.md)；本页不重复具体Bug批次或验收结果。

V1起步选择平地/墙滑/跳跃与有限坡台，自研角色规则配合Jolt后端；长期平台/推箱目标保留。绑定/原生版本和部署集中在[dependencies.md](../guides/dependencies.md)。

本页细化 [plan.md](../plan.md) 中的物理/角色部分，连接 [assets-scene-roadmap.md](assets-scene-roadmap.md)、后续动画、Gameplay 和工具。已有固定模拟 60 Hz、controller 驱动世界位移、in-place 动画、镜头相对移动及首块平地/墙面验收继续有效；本页不重新询问这些选择。

## 1. 已确认的选择

| 议题 | 助手推荐 | 另一方案 | 状态 |
| --- | --- | --- | --- |
| 此前已选角色/物理目标 | 分块加入斜坡台阶、平移平台和受控推箱 | 基础版先到斜坡台阶，平台/推箱后置 | 原长期目标保留；V1选择有限坡台，平台/推箱后移 |
| 角色规则分工 | 自研移动规则，后端提供查询与刚体能力 | 优先适配后端现成控制器，再独立补原理实验 | 用户选择自研角色移动规则 |
| 进阶实践组织 | 各类先独立代表实验，再按需接入 | 优先深入整合布娃娃/布料，破坏/车辆后置为独立实验 | 用户选择独立代表实验、按需整合 |

上述选择分别确定能力目标、项目与后端分工、专题组织；库具备某功能不证明本工程集成，也不批准新的原理实验或能力范围。

<a id="layers"></a>
## 2. 推荐的三层实践

| 层次 | 目的与候选范围 | 不能冒充的完成程度 |
| --- | --- | --- |
| 自研原理实验 | 少量简单形状上实现积分、力/冲量、转动惯量、候选筛选、碰撞/接触与小约束，能够观察中间结果 | 不因小球反弹就称已完成通用稳定刚体后端 |
| 训练场集成 | 成熟后端承担所选碰撞与动力学能力；项目负责对象映射、生命周期、时间同步、事件、过滤和角色规则 | 调用库不代表自己实现了其所有内部算法；第三方示例也不是本工程能力 |
| 进阶代表实验 | PBD/XPBD、布料、布娃娃、预分块破坏、简化车辆等分阶段实践 | 不承诺完整衣物自碰撞、任意切割、工业轮胎或完整物理动画系统 |

自研实验与训练场后端可以并存。建议先建立一个能观察的基础场景，再穿插实验与集成；不要求从零写完工业级物理后端才让角色运行。以下 P 编号是模块内部讨论分块，不是全项目顺序。

<a id="principles"></a>
## 3. 自研原理实验：候选最小范围

| 分块与笔记 | 实验建议 | 验收与解释 |
| --- | --- | --- |
| P1 运动与积分：第 2 章 | 小球/弹簧；比较显式与半隐式积分，区分持续力和单次冲量 | 对照解析解或能量变化；解释步长误差、重复施加冲量和稳定性边界 |
| P2 转动：第 3 章 | 对同一物体质心/偏心位置施力，改变质量分布或惯量 | 平动与转动差异可见；说明力矩、角冲量与惯量的作用 |
| P3 检测：第 4–5 章 | 全配对基线与一种简单 Broad Phase 比较；解析球/平面等接触；GJK/SAT 后续选择可视化实验 | 显示候选对、接触点/法线；包围盒重叠不能代替精确检测；具体算法数量未定 |
| P4 响应与约束：第 6/13 章 | 少量接触的冲量响应、距离或关节约束小例子 | 观察反弹/摩擦或约束误差；区分接触/非接触约束与冲量式/位置式求解路线 |

维度可从二维或有限三维问题起步，再扩大；具体实验数据结构和测试场景须在对应任务中决定。每项记录时间步、参数、误差及失败现象，不能只展示看似正常的动画。

<a id="character"></a>
## 4. 训练场中的物理与角色能力

训练场集成起步为受控静态环境、自研角色和后端有限查询/刚体适配；长期覆盖坡台、平台、推箱与配套能力。动态Gameplay、通用Trigger、平台/推箱不能仅从后端接口推为演示能力。

- 逐步接入静态环境、动态刚体、受控运动机关和 Trigger；质量/惯量、摩擦/恢复、力/冲量分别说明。Trigger 是触发关系而非普通实体墙，不能仅创建一个名为 Sensor 的层就算完成。
- Raycast、Sweep、Overlap 分别用于射线命中、沿运动路径检测和当前位置重叠检查；明确是否忽略自己、查询过滤、命中顺序以及未命中时的结果。
- 用户已确认的首个控制器检查点保持：平地移动、墙面阻挡/滑动、跳跃、落地和撞顶；斜向速度与一次跳跃请求的消费要可验证。
- 有限可走/不可走坡与台阶需要边界检查，复杂坡台组合另定；后续平移平台涵盖携带/上下/跳离，受控推箱另设验收。旋转平台/复杂挤压和高级动作不因“能站平台”自动包含。
- 角色控制器不等于Kinematic刚体。项目规则使用ray/sweep/精确重叠处理去穿透、滑动、接地与有限跨步；库的查询矩阵适配须在边界固定并验证，不能套到场景/GL矩阵。
- 保留逻辑 Transform 的明确写入者：角色由控制流程提交实际结果，动态物体由物理回写，动画不额外写角色世界位移。表现插值不回写模拟；NPC 可复用运动能力，但寻路/避障决策另属 AI。
- 物理边界管理过滤/身份映射，机关在安全模拟边界改变Body状态；有限Gameplay触发与通用后端Trigger回调不同。扩展回调要在安全阶段收敛，不能遍历时任意增删对象。
- 工具应可查看碰撞外壳、查询路径、地面/接触信息、实际速度及逻辑/显示位置，服务验收而非仅装饰画面。

<a id="runtime"></a>
## 5. 运行保障的实践边界

| 主题 | 候选验证 | 限制 |
| --- | --- | --- |
| Sleeping/唤醒 | 静止后进入休眠、受力或相邻交互后唤醒 | 不要求立即自研生产级 Island 划分器；要区分后端能力与自己的集成 |
| CCD | 高速小球与薄障碍，对比离散检测和选定的连续处理 | 不给所有物体默认开启；具体后端可支持的运动/形状范围待核对 |
| 重复运行 | 相同初始状态和输入序列的结果检查，记录误差与保证范围 | 固定 60 Hz 不等于跨平台逐位确定性，也不提前承诺锁步网络 |
| 创建/删除/重载 | 对象注销、事件解绑、运行句柄映射和失败回滚 | 继续采用新场景成功后才替旧场景；不能让暂存场景对象操作当前旧场景的物理世界 |
| 时间与显示 | 固定模拟/表现分离、暂停/卡顿/插值历史按统一时间合同处理 | 原M1参数不因合并生效，现行V1合同在架构/指南 |

后端的库级初始化与场景物理世界寿命必须分开。所选后端要能支持新旧场景在准备/切换期间的正确所有权；不能照搬参考中的全局槽位使用方式并宣称可安全并存。

<a id="advanced"></a>
## 6. 进阶专题候选深度

| 专题与笔记 | 代表实验 | 依赖与边界 |
| --- | --- | --- |
| PBD/XPBD：第 13 章 | 先距离约束链，比较步长、迭代数和柔度，再扩展到布片 | 观察误差；不宣称 XPBD 消除了所有步长/迭代影响 |
| Cloth：第 10 章 | 小型固定点布片、重力/风与简单障碍碰撞 | 可与 PBD/XPBD 共用渐进实验；完整服装、自碰撞、任意拓扑另定 |
| Ragdoll：第 9 章 | 少量刚体与关节限位，映射回骨架并观察动画/物理交接 | 依赖骨架与姿态能力；可以用跌落演示，不需引入战斗 |
| Destruction：第 11 章 | 预先分块物体，断开连接、激活碎片并回收 | 不等于运行时任意网格切割或真实材料断裂 |
| Vehicle：第 12 章 | 单车身、简化悬挂及驱动/制动/侧向力，观察起步转弯越障 | 依赖可靠刚体与查询；不承诺专业轮胎/传动模拟 |

用户已选择各类先做独立代表实验，再按需整合；不要求每个子算法都达到工业级。上表是候选最小实现形式，具体算法、工具和最低验收再逐块定案，不能据此声称全部系统接口已确定。

## 7. 自研/后端边界与 Piccolo 参考

物理选型比较能力、绑定、部署与查询适配后采用Jolt，Bepu为未采用备选，不仅因Piccolo使用Jolt。集成查询/双世界/基本刚体与自研角色，不等于完整动力学、所有形状/CCD/Joint/Trigger；细节及比较理由见依赖指南。

Piccolo 固定 f5053707fed4d3f94d270a436fb0d3a8ae54e3e5 已核到 Jolt 三类查询、碰撞层过滤及静态形状创建；角色仅目标重叠检查，所查创建链仍为 Static，不能称完整动力学/Trigger/Joint 系统。仅改运动类型枚举不会自动补齐质量/惯量、物理回写、事件、调试和验收。详见 [design-reference-checks-2026-10-03.md](../reviews/design-reference-checks-2026-10-03.md)。

外部机制参考可查 [PhysX 5.3 角色控制器说明](https://nvidia-omniverse.github.io/PhysX/physx/5.3.0/docs/CharacterControllers.html)、[Jolt 5.3 CharacterVirtual 说明](https://jrouwe.github.io/JoltPhysicsDocs/5.3.0/class_character_virtual.html)。这些文档用于比较角色控制与刚体的关系，不表示本工程或 Piccolo 已采用这些版本/实现。

笔记入口见[learning-map.md](../learning-map.md)物理章节。原理实验观察步长/参数/误差和失败，集成学习查询矩阵/feet位置/实际位移写入者；角色极端组合、Sleeping/CCD与各进阶专题另定算法、深度和证据。

平台/推箱、独立积分/检测/接触与布娃娃/布料/破坏/车辆等长期目标均保留，代表实验的选择及整合范围须按专题收敛；不是所有算法同时实现的承诺。
