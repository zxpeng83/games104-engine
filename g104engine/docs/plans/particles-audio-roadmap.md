# 粒子与声音：生命周期、空间反馈与代表实验

本页维护粒子/声音的已选终点、模拟/表现/设备职责与后续实践。V1范围在[v1-baseline.md](v1-baseline.md#scope)，GPU粒子、复杂表示与传播/流送等候选须另行收敛。

现行生命周期/格式/播放入口见[architecture.md](../architecture.md)和[dependencies.md](../guides/dependencies.md)，代码—笔记映射见[learning-map.md](../learning-map.md)。各批功能/听感证据单独维护，本页不重复验收结果。

本页细化 [plan.md](../plan.md) 的粒子与声音，连接 [gameplay-ai-roadmap.md](gameplay-ai-roadmap.md)、[animation-roadmap.md](animation-roadmap.md)、[rendering-roadmap.md](rendering-roadmap.md) 和场景资源生命周期。用脚步尘土、机关启动、喷泉/环境声等非战斗示例，不扩大已选训练场玩法范围。

<a id="choices"></a>
## 1. 已确认的选择

| 议题 | 助手推荐 | 另一方案 | 状态 |
| --- | --- | --- | --- |
| 粒子路线 | 先 CPU 生命周期/Billboard，再 GPU Compute 实际对比 | GPU 主线先行，CPU 独立补原理实验 | 用户选择 CPU 先行，再做 GPU 对比 |
| 基础声音终点 | 2D/3D 播放、方位距离、一次性/循环事件及基本播放管理 | 同时纳入简单遮挡与区域混响 | 用户选择推荐终点，遮挡/混响后续实验 |
| 第三人称 Listener | 跟随相机位置与朝向 | 角色位置＋镜头朝向 | 用户选择相机位置与朝向作为起步方案 |

基础方案选择OpenTK OpenAL绑定配合OpenAL Soft设备后端、离线PCM输入；粒子/Voice采用有限容量与可解释淘汰/回收策略。精确版本、素材/许可、转换和当前容量集中在依赖/架构指南。

<a id="data-layers"></a>
## 2. 先区分模板、实例和可见/可听结果

| 层次 | 粒子 | 声音 |
| --- | --- | --- |
| 可复用资产/定义 | Emitter/Effect 配置、材质、贴图和几何 | Clip、音频事件定义、播放与空间参数 |
| 一次运行实例 | 本次效果及其粒子池、年龄、速度和寿命 | 本次 Voice/Source 的位置、进度、循环与优先级 |
| 面向观察者的结果 | 当前相机可见列表、排序和绘制几何 | 当前 Listener 的方位、距离参数及后端混音输出 |

同一模板或 Clip 可产生多个独立实例。离开视野不自动等于粒子死亡；逻辑声源存在也不等于必须占用一个实际播放通道。场景卸载时按各自所有权停止使用并清理，不能仅删除 GameObject 引用就认为后端资源已释放。

<a id="particles"></a>
## 3. 粒子起点与后续分块

FX编号只用于模块讨论。FX1/FX2给出CPU有限生命周期/Billboard起点，持续Emitter/复杂表示与FX3 GPU对照、FX4质量实验后续分期；GPU粒子不等于GPU几何专题。

| 分块 / 笔记 | V1有限实现 / 长期候选 | 验收与学习方向 |
| --- | --- | --- |
| FX1 生命周期：第2–3章 | 世界空间Burst、年龄/寿命/受控随机/运动回收/alpha淡出起步；可复用Emitter、持续发射与复杂曲线后续 | 出生/回收/满容量有定义，持续发射说明速率与停止策略；寿命不按显示帧号累计 |
| FX2 基础绘制：第 4–5 章 | Billboard、深度与透明合成、必要排序/近似及统计 | 转动镜头方向正确；不把 Alive 列表顺序当透明顺序；观察过度绘制与排序限制 |
| FX3 GPU 对照：第 6 章 | 按已选 CPU 先行路线，保留同类效果的 CPU 基线，再 Compute 更新/池管理/绘制数据准备 | 比较模拟、同步和绘制成本；不预先保证 GPU 总更快或两端浮点结果逐位相同 |
| FX4 表示与质量专题：第 4–7 章 | Mesh/Ribbon/Flipbook、低分辨率合成、Depth/SDF 近似碰撞及有限可编程行为选代表实验 | 各自有可观察效果、质量与成本边界，不先做完整 Niagara 式创作系统 |

需明确模拟 Alive 与相机 Visible 的区别、发射器局部/世界空间、随机种子、停止发射后存量粒子的处理和安全释放。若离屏降频或暂停模拟，应说明时间/恢复策略，不能无意把离屏粒子回收成死亡。

屏幕深度只描述有限的可见表面；用其反射粒子速度是视觉近似，不是权威物理碰撞事件。真实 Gameplay 触发或 AI 事实仍由已有规则/物理入口提供。GPU 排序、原子计数、内存布局、同步、回读和间接绘制应分别学习并测量，不能只看到 Compute 调用就认定整个路径没有 CPU 等待。

<a id="audio"></a>
## 4. 声音终点与后续分块

基础声音通过成熟device/context/buffer/source后端实际输出，项目负责PCM读取、独立Voice/Listener与有限清理；共享Clip与播放实例分开。初始化/播放/暂停/停止/退出和用户听感分别验收，不能推为所有设备/声学组合已覆盖。

| 分块 / 笔记 | 基础能力 / 后续候选 | 可听/可观察验收方向 |
| --- | --- | --- |
| AU1 Clip/Event/Voice：第 10/13/21 章 | 共享音频资产、一次性/循环事件、独立播放实例，基础开始/停止/完成回收 | 同一 Clip 多次播放互不混淆；循环能正确结束；重复事件不无意堆积 Voice |
| AU2 空间声场：第 14–16 章 | 区分 2D 提示与 3D 世界声；Source/Listener、方位和距离参数 | 转动镜头/移动声源可听辨方向和远近；UI 声不随场景旋转漂移；不宣称已经具备 HRTF 的全部前后/高度线索 |
| AU3 基础管理：第21–22章 | 有限Voice预算、可解释淘汰/事件消费/完成回收与场景清理起步；分类/优先级后续 | 观察循环和实例清理；简单上限策略不等于完整虚拟Voice/中间件预算系统 |
| AU4 场景传播（后续专题） | 用户本次未纳入基础版，后续分别实践遮挡与区域混响 | 验证参数来源与过渡，不能直接把射线命中墙面等同于静音 |

60 Hz 是游戏模拟频率，不是音频采样率；后端按自身缓冲和采样节奏处理声音。游戏提交事件/空间参数，不在每个物理步重新开始播放 Clip。音频回调线程、命令提交及设备/资源清理规则按已选后端落实并验证，不能照搬 OpenGL 上下文模型。

<a id="feedback"></a>
## 5. 第三人称听者与跨系统反馈

用户已选择 Listener 跟随相机位置与朝向：听觉参考与画面观察点一致，但相机拉远或隔着门会改变距离与传播条件。角色位置＋镜头朝向是另一种取舍；后续可用明确 A/B 听感实验调整，不把初始约定当成唯一正确答案。

- 粒子与声音消费同一已提交事件的语义、时刻和位置，但寿命可以不同；尘土消失不自动截断声音尾部。
- 动画marker与已提交Gameplay事实是不同来源；具体声音/粒子订阅在现行架构明确，不能从“动画有事件”推断已接脚步音，也不在每次Pose/绘制重发。扩展反馈须选择唯一有效来源并去重。
- Listener 与声源位置/速度的时间依据要明确，瞬移不应被当作连续的极大速度；Doppler 等具体功能仍按范围分期。
- 玩家最终听到的混音与 AI 听觉是不同职责。NPC 使用玩法刺激和感知规则；用户静音或 Voice 被预算抢占，不应自动改变 NPC 是否知道某个事件。
- 音频Buffer驻留寿命与Voice播放寿命分开，Play/Stop清理播放实例不必反复释放共享Clip；长内容流送/虚拟Voice/细优先级另行设计。具体资源作用域与上限在架构/依赖说明。

<a id="advanced"></a>
## 6. 声音及表现的后续代表实践

| 主题 | 候选实验 | 边界 |
| --- | --- | --- |
| 数字音频与声像：第 12–15 章 | 波形/采样/量化或等功率左右声像小实验 | 理解信号与听感，不自研整套实时设备输出系统 |
| 遮挡/遮蔽：第 17 章 | 查询环境后调整音量/滤波并平滑变化 | 射线近似不等于完整绕射/声传播；所需后端能力未选 |
| Reverb：第 18 章 | 两种区域/参数的混响对比与过渡 | 不承诺真实建筑声学或波动方程求解 |
| Doppler：第 19 章 | 声源经过听者的相对运动实验 | 区分径向速度、更新时钟与瞬移，具体缩放参数待定 |
| HRTF/Ambisonics：第 15/20 章 | 耳机空间化、声场旋转/解码分别实验 | 两者不是同一种数据和能力，不宣称基础左右声像已覆盖全部空间化 |
| 流送/预算：第 22 章 | 短驻留和长内容分块播放对比，观察延迟/欠载/清理和更细优先级 | 后端支持某功能不等于本工程已经接入；完整中间件创作工具另评估 |

以上候选实验与基础范围的具体分期仍需收敛。用机关、环境和脚步即可验证，不因原笔记出现爆炸案例而添加战斗。

<a id="references"></a>
## 7. 参考、未决事项与接续

Piccolo 固定版本已核到粒子池、GPU 发射/模拟和 Billboard 主链，也有 CPU 计数回读与等待，所查路径无透明排序阶段；深度碰撞受屏幕可见数据限制。自有 runtime/构建清单与初始化路径未发现完整声音接入链。细节见 [design-reference-checks-2026-10-03.md](../reviews/design-reference-checks-2026-10-03.md)，不把第三方能力或 API 名称视为本工程已有功能。

外部机制参考：[OpenGL Compute 调度说明](https://github.com/KhronosGroup/OpenGL-Refpages/blob/main/gl4/glDispatchCompute.xml)、[OpenAL Soft 官方项目](https://github.com/kcat/openal-soft)。OpenTK.Audio.OpenAL＋OpenAL Soft 的组合已选择，具体准备和验证状态见清单；不代表接入 FMOD/Wwise 等其他音频系统。

后续保留GPU同步/持续Emitter/复杂粒子、音量分类/预算及传播/HRTF/Ambisonics/流送。专题前确定代表实验与验收，理解一次事实如何产生Burst/Voice和释放资源；路线不自动扩入V1。
