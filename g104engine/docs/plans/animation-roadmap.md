# 动画模块：运行时、动作控制与进阶实践

本页维护动画的已选终点、实现理由与后续实践；V1边界集中在[v1-baseline.md](v1-baseline.md#scope)，未来专题须另行收敛范围与授权，不从路线表推断完成。

可选现行知识与代码入口：[rendering-and-animation.md](../guides/rendering-and-animation.md)、[learning-map.md](../learning-map.md)。本页不重复各批修复与验收结果。

本页细化 [plan.md](../plan.md) 的动画部分，连接 [assets-scene-roadmap.md](assets-scene-roadmap.md)、[physics-character-roadmap.md](physics-character-roadmap.md) 和 [rendering-roadmap.md](rendering-roadmap.md)。沿用已确认的 glTF 2.0/GLB 输入方向、controller 驱动世界位移、in-place 基础动画和明确状态归属；不重新选择这些事项。

## 1. 已确认的选择

| 议题 | 助手推荐 | 其他候选 | 状态 |
| --- | --- | --- | --- |
| 基础训练场动画终点 | Idle/Walk/Run 速度混合、跳跃状态机、平滑过渡与基础事件 | 基础版再包含上下身分层、Additive 和基础脚部 IK | 用户选择推荐终点；局部组合/IK 后续实验 |
| 控制组织 | 小型可配置状态机/混合运行时，先提供状态/权重调试显示 | 先代码固定流程；或基础阶段同时制作完整可视化节点编辑器 | 用户选择小型可配置运行时与调试显示 |
| 初期素材 | 同一骨架的一组相容动作，重定向另做专题 | 基础版支持跨骨架复用与多个角色 | 用户选择同骨架动作集起步 |

初期采用同骨架非Root Motion素材；格式解析与自研采样/混合/蒙皮职责分开。输入支持与配置细节见渲染/动画指南，素材来源/许可见[dependencies.md](../guides/dependencies.md)。

<a id="data-flow"></a>
## 2. 先打通可解释的数据流

可解释的动画主线是：**动画资产和时间 → Local Pose → 混合/过渡 → 骨骼层级求值 → Skinning Palette → GPU 蒙皮 → 画面**。Gameplay/控制器提供实际速度、是否接地及已经发生的起跳/落地事实；动画决定如何表现，不因为正在播放Landing就倒推出已接地。

- 格式库可负责读取资产，采样、姿态组织、混合、层级求值和蒙皮运行流程按项目的关键原理自研方向实现；不先接入完整现成动画引擎来替代这条学习链。
- Skeleton、Clip 和绑定数据可作为共享资产；播放游标、状态机状态、过渡进度与实例 Pose 属于各角色，不能因共享模型而让所有角色同步使用同一份可变播放状态。
- 动画采样插值、跨 Clip 混合和固定模拟状态的显示插值是三个不同概念，不能只用一个“插值”词代替各自契约。
- 模型/骨骼/Actor 空间与已选 CPU 行向量、GLSL 列向量映射保持一致。完整绑定链下，Bind Pose 应保持预期几何；要先明确 Mesh/Node/Bind 空间，不能不分空间地要求任何原始矩阵直接等于单位矩阵。
- 多个绘制 Pass 若使用变形模型，应消费一致的姿态；主画面、阴影、后续拾取和包围体要分别验证，不能主画面能动就算全部正确。

<a id="practice"></a>
## 3. 基础运行时与后续实践分块

AN编号保留模块讨论顺序，不是统一排期。AN1–AN5说明基础终点与学习验收方向，AN6为后续专题；具体实现和覆盖证据由指南/评审维护。

| 分块 / 笔记入口 | 基础能力 / 后续候选 | 验收与学习方向 |
| --- | --- | --- |
| AN1 骨架与绑定：第 5–19 节 | Skeleton 层级、局部/模型空间 Pose、绑定关系、Palette 和线性混合蒙皮（LBS）；从少量骨骼/顶点算例到 GPU | 绑定姿态不改变预期几何；父链、索引、权重正确；世界变换不重复施加；骨架线与模型能对应 |
| AN2 单 Clip：第 20–22 节 | 按真实关键时间采样 Local TRS，处理播放/暂停/循环和输入格式插值契约 | 指定时间与已知姿态一致；速度不由绘制帧号决定；循环与四元数符号处理可验证 |
| AN3 连续移动：第 34–36 节 | 各自采样后做跨 Clip 混合，一维 Idle/Walk/Run；协调步态相位、速度和播放率 | 权重两端还原对应动作；速度变化连续；撞墙或实际减速后表现能解释；显示滑步与相位问题 |
| AN4 跳跃与事件：第 41–48 节 | 起跳/空中/落地状态与平滑过渡；事件和必要参数驱动 | 动画消费控制器事实；起跳拒绝时不凭按键重复播放；事件跨循环/低帧率不漏，多次显示不重复 |
| AN5 可配置与调试：第45–47、74–75节 | 有限状态配置、Clip映射/速度/时长/事件及状态/权重/骨架显示，不要求通用动画图节点系统 | 能改变配置、区分实例与显示插值；解释Pose和控制流，不把有限配置称完整节点编辑器 |
| AN6 局部组合/环境修正 | Mask、Additive 与 Two-Bone IK 留到后续专题，不自动纳入本次选定基础终点 | 能单独看到局部动作和环境修正影响，不把算法存在当作自然动作已经完成 |

“动作能播放”不是终点。基础状态机和混合应能解释什么时候换动作、为什么使用这个权重、哪个输入属于 Gameplay 事实，以及哪些问题来自素材而非代码。

<a id="contracts"></a>
## 4. 输入和时间的技术边界

- glTF 的 Track 时间以秒记录，各通道可以有不同的关键时间；不能把所有动画视为 Piccolo 示例那样的统一等间隔帧序列。未被动画修改的通道保留相应源节点静态变换，不自动填单位变换或从 inverse-bind 反推所有局部姿态。
- V1输入边界选择STEP/LINEAR与归一化短弧旋转，CUBICSPLINE明确拒绝。后续扩展时须处理切线/时间间隔及旋转归一化，不能直接当SLERP或忽略切线。
- 对不支持的采样器/数据给出可定位诊断，或采用经过验证的重采样流程；不把静默降级后的播放写成完整格式支持。
- 逻辑动画、编辑预览与显示插值应分别说明时间来源；重复绘制不推进逻辑或重发事件，暂停/恢复/切场景清理各自历史。固定60Hz不等于所有未来动画求值必须同频。
- 事件按播放经过区间及有效状态来源处理，考虑低帧率、循环、混合及重复显示去重；单纯判断当前时间等于marker会漏发。扩展混合层/事件类型时重新定义来源与验收。
- 基础事件可先用可视标记或日志验收，再接声音/粒子模块。关键玩法成立条件不能只依赖某张图是否被绘制或某个视觉事件是否触发。
- in-place仍可能脚滑；一起检查实际速度、步幅、播放率和相位。时间契约正确与素材在任意速度/地形都自然是不同验收问题。

语义参考：[Specification.adoc](https://github.com/KhronosGroup/glTF/blob/main/specification/2.0/Specification.adoc#animations)、[ozz 作者的混合示例](https://guillaumeblanc.github.io/ozz-animation/samples/blend/)。后者用于理解组合与时间同步，不表示本项目已选择 ozz 库；实现时固定实际采用的参考代码版本。

<a id="advanced"></a>
## 5. 进阶代表实践与覆盖边界

以下为建议清单，具体深度与先后仍需整体路线和专题设计确认，不把每个子算法都承诺为工业级实现。

| 笔记主题 | 候选代表实验 | 边界与依赖 |
| --- | --- | --- |
| 2D、VAT、其他表示：第二部分 | Sprite/Flipbook、小型 2D 形变或 VAT 播放实验 | 区分图像、逐顶点时间数据与骨骼姿态；不宣称完整 Live2D 或通用角色制作工具 |
| 局部混合：第九/十部分 | 上身 Mask、呼吸/挥手等 Additive、二维 Blend Space 的代表例子 | 用非战斗内容即可；明确参考姿态、遮罩交界、时间同步和相容素材 |
| IK：第十一部分 | Two-Bone 独立实验，再脚部接触；长链从 CCD/FABRIK 选代表算法 | 数学命中目标不等于自然步态；Foot Lock、骨盆补偿、Pole/关节限制和移动平台空间另验 |
| Morph/面部：第十二部分 | 几个 Morph 的组合、骨骼/材质配合的简单表情或口型 | 保留实践，但不声称完整 FACS、面捕、肌肉模拟或自动唇同步系统 |
| Retarget：第十三部分 | 两套骨长/参考姿态不同的骨架，验证映射与手脚接触误差 | 同名骨骼不等于可直接复制；需要可靠语义和参考姿态关系 |
| 压缩：第七部分 | 常量 Track、关键帧约简或量化选代表方案，对照原始曲线 | 同时测体积/解码成本和末端可见误差；不以压缩率一个数字代替质量 |
| 性能：第十五部分 | Pose Cache、Animation LOD、批处理或并行求值按需求分期 | 少算 Pose 时仍需维护必要逻辑时间和事件；不预建完整 Job System |
| Root Motion：第六部分相关专题 | 提取位移并经控制器/碰撞消费的独立实验 | 基础 in-place 不变；根位移只能应用一次，不能绕过既定运动状态归属 |
| 物理动画：跨物理模块 | 与已规划 Ragdoll/Cloth 实验衔接姿态和状态切换 | 共用相关物理专题，不另建重复项目或默认为基础版已包含完整混合 |

理论总览、综合案例、调试清单和实践顺序通过数据流与验收贯彻，不需要为每个笔记标题创建独立系统。复杂分层状态机、完整动画树编辑器、多目标 IK、Motion Matching 等保留后续深度讨论。

<a id="materials"></a>
## 6. 素材与学习验收

选定同一骨架相容动作可避免基础阶段先做重定向；同为glTF或人形不保证骨轴、层级、参考姿态、相位或命名相容。实际素材/许可见依赖指南；未来更换素材仍需实查，不能假定任意网上动作直接混合。

每块应有暂停、单步/指定时间、骨架/关节或状态/权重等足以说明结果的调试手段；实际工具能力随阶段引入，不一次性建设完整 Animator 界面。检查绑定、关键时间、循环、过渡、事件、不同显示帧率及实例独立性；实验代码与笔记章节、固定参考和简化方案写入 [learning-map.md](../learning-map.md)。

Piccolo 固定版本可参考骨架、采样、Palette 与 GPU 蒙皮链；多 Clip 混合权重未在实际求值中生效，关键帧消费也不能照抄为 glTF 绝对 Local TRS。来源与跨 Pass 限制见 [design-reference-checks-2026-10-03.md](../reviews/design-reference-checks-2026-10-03.md)。

基础动画之外，Mask/Additive/IK、重定向、压缩、Root Motion、Morph/面部与性能等深度须按专题收敛。未来实践表保留学习目标，不自动扩入V1；全局阶段仅由总体计划安排。
