## 1. 本次调整的目的与状态

用户希望基础训练场少放进阶内容，将进阶实践推到后续版本，先取得可用于面试的成果。助手赞成这一方向，建议把长期模块覆盖与首个展示版本的验收分开管理。此前全模块都要不同程度实现与掌握的目标仍保留；原已确认的实现路线与终点不因本建议被删除。

用户已统一名称为 **基础综合训练场 V1**，并注明 **用于面试展示**。此前“面试 Demo”“面试 V1”均指这个版本，不另设一套面试工程或独立交付范围。Deferred与Undo/Redo已明确进入V1；“最小3D里程碑”也已合入V1，不再独立审批，基础绘制成为内部工作。具体契约以 [完整实施方案](v1-implementation-draft.md) 第3/7/9节为准；网络/GI/GPU几何精细讨论继续暂缓。

建议成功标准：一个短而完整的第三人称非战斗演示，能稳定运行、重置和观察关键状态，用户能解释核心数据流、取舍与已知限制。表现质量与功能深度服务演示目标，不以是否同时具备所有进阶算法判断首版完成。

基础综合训练场 V1 仍有跨模块工作量；“简单”指限制场景、资产、功能变体和工具深度，不删去行为正确性。可控制 NPC 导航在平坦区域，玩家坡台测试另设区域；不承诺网格导航自动支持全部坡台、平台和多层建筑。

Play/Stop 已纳入 V1，须满足保护未保存设计的已选语义；运行状态不自动写回设计文件。有限编辑仍须处理共享资源、失败清理、数据一致性和 UI 输入。

### 2.1 Deferred 在 V1 的建议深度与验收

保持 Forward 先行路线，已有场景/材质/光照输入尽量共用，再实现不透明几何的 G-buffer 与独立光照阶段，提供法线、深度和材质等中间结果的观察方式。具体附件数量、格式、坐标空间、位置重建及灯光预算待设计；不因纳入 Deferred 自动增加完整 Render Graph、Tiled/Clustered、SSAO/TAA 或 IBL。

建议 V1 的透明对象/粒子保留 Forward 绘制，并衔接不透明深度；几何姿态、蒙皮、材质和阴影输入要与 Forward 基线保持约定一致。参考 [Deferred Shading](https://learnopengl.com/Advanced-Lighting/Deferred-Shading) 的 G-buffer/光照与混合管线说明，教程的传统光照字段不直接作为本工程 PBR 数据契约。

分块验收建议：G-buffer写入/显示 → 光照与深度衔接 → 同场景Forward/Deferred对照；检查窗口尺寸、渲染目标释放与失败清理。实施方案第9节已定为编辑态选择模式、下次Play生效；不承诺Deferred总更快。若展示性能结论，在此节点按需补相应计时，不把初版FPS当作GPU时间，也不自动建设完整Profiler。

### 2.2 Undo/Redo 在 V1 的建议深度与验收

限定为约定的场景设计操作。V1 已包含支持对象的创建/删除、Transform 与少量组件参数编辑，可按参数操作再结构操作的顺序实现；复制及其他命令另列清单，不因存在 Undo 栈就宣称任意操作可撤销。运行中的位移、动画时间和临时状态不进入设计历史。

实施方案已采用统一编辑命令及校验，再记录执行前后数据或对应恢复信息。一次拖拽合并为一次操作、取消恢复原值，新设计操作清空Redo，历史起步100条可调；子树删除及外部引用拒绝规则见第7/9节。撤销恢复约定对象数据/身份/引用，不保存GPU或物理句柄作为恢复数据。

分块验收建议：数值编辑→Undo→Redo → 拖拽合并/取消 → 选定结构操作与保存/重载一致性。历史容量、未保存标记、换场景与 Play/Stop 的历史处理仍需明确；不能让旧场景命令修改新场景。先把可撤销编辑的数据入口做好，再接面板，减少后期重做修改路径。

两项均可在既有技术基线中分块实现，但会增加 V1 的资源管理、编辑数据和回归验证工作；没有可靠依据提前承诺具体工期。它们分别在有可用渲染主线和可编辑场景数据后验证，不要求首次基础绘制就完成全部。

## 3. 候选演示与深度证据

可用约 3–5 分钟的演示路线组织：角色进入训练区并走跑/跳跃 → 操作按钮或进入触发区，使门/目标状态改变 → NPC 感知并绕过静态障碍跟随，丢失目标后搜索 → 展示动画、粒子、声音反馈 → 打开调试显示追踪一段状态变化 → 重置场景再次演示。时长与关卡流程只是建议，不是已批准验收数字。

建议准备三条能深入解释的链路：

- 输入→移动意图→碰撞查询/角色规则→逻辑姿态→动画与相机。能解释接地、墙滑、时间步及状态写入者。
- 感知→FSM→路径→运动执行→到达/失败反馈。能解释何时重新寻路、路径失败与控制器受阻的区别。
- 设计数据/共享资产→运行实例→事件反馈→重置/释放。能解释实例与资源寿命、订阅清理及编辑/运行边界。

不降低正确性验收：异常输入、重复触发、找不到路径、对象销毁、连续重置和加载失败要有明确处理。先在已有本机环境记录验证；本提议不恢复暂缓的 D5 独立克隆、CI 或第二设备测试。

面试材料候选包括可运行成果与启动说明、短演示视频、架构/数据流图、关键代码入口和笔记映射，以及少量真实问题定位与修复记录。用户除观看结果，还应能独立解释、调参、定位问题并做小范围改动；自研、第三方集成和工具辅助的分工如实说明。打包/发布/上传等动作均未授权或执行。

## 4. 后续版本如何承接

建议先保留“基础综合训练场 V1 → 能力扩展与方案对比 → 进阶专题”的层次，后两类内部再分多个里程碑，不现在冻结一个庞大的 V2 或把所有专题塞进 V3。每次扩展从已验收基线出发，保留有教学价值的对照实现，按实际情况选择切换/重载或独立实验。

V1 内部按渲染/场景基础、角色与动画、交互/NPC、表现与工具等能力增量实现并验证。用户希望加快开发、尽量一次取得完整 V1；较大预览节点和是否等待反馈的节奏正按下方方案讨论，不把每项内部技术检查都变成一次用户审批。

后续网络/GI/GPU几何等主题可以先登记目标与依赖，精细接口/算法在各自实施前再收敛；不要求把所有未来专题细节全部设计完才能启动已经批准的小阶段。真正进入代码仍需完成近期设计审阅和对应实施授权。

### 4.2 加快开发：一次版本任务、内部持续验证（随开工方案审阅）

用户希望尽可能一次开发好整个基础综合训练场，以减少等待、加快取得面试成果。助手建议在集中确认 V1 范围、依赖/素材和执行方案后，以完整 V1 为一次开发任务连续推进；内部仍增量编写、集成、构建/调试和必要验证。常规实现、局部修复和已有约定内的技术处理不逐项提问，进度与文档持续更新。

建议提供两个中途可运行预览和最终交付：角色/碰撞/动画可体验；Gameplay/NPC/Deferred/Undo 等形成约定闭环；最终回归、运行说明与学习材料。实施草案按预览不强制停工准备，并在开工弹窗一并确认；它们不是三个发布版本，未取得的用户运行/手感/试听反馈仍标为待验收。

“连续完成”描述任务组织与交付目标，不保证单次生成就正确，也不要求同一聊天容纳全部工作；跨对话按既有持久化规则接续。大功能联调时提前验证有助于较早暴露错误，避免最后集中定位，见 [DORA：小批次工作](https://dora.dev/capabilities/working-in-small-batches/)。这不恢复 D5/CI，也不采用外部资料里的自动提交或部署做法。

开始实施前集中收敛三类事项：

- **V1的具体边界**：范围已确认，不再重问；灯光/材质/导入子集、有限坡台、编辑命令和验收按实施方案，实际效果开工后验证。
- **依赖与素材**：模型/图像解析、物理、UI、音频方案及版本、同骨架模型/动作准备；助手先提交具体推荐和准备清单，用户按既有分工在 VS 配置/还原。本次未选库或安装。
- **运行契约与完成标准**：输入/时间、编辑/运行和数据归属、场景/资源清理，以及可观察演示与验证口径；只细化足以执行 V1 的部分，不穷尽未来专题。

遇到改变已选方案、扩大范围、需新依赖/环境操作或需要用户确认的体验取舍时，说明具体问题和推荐方案；能独立推进的工作继续。当前完整安排见 [V1 实施草案](v1-implementation-draft.md)，依赖组合已选择，具体准备见 [版本/素材清单](v1-dependencies-and-assets.md)；尚无开工弹窗同意记录。

## 5. 建议的依据与尚待确认事项

本建议主要依据用户的短期 Gameplay/客户端目标、当前只有理论背景、已选模块路线与现有空模板/探针基线。固定 Piccolo 的具体能力与限制已在 [参考核查](../reviews/design-reference-checks-2026-10-03.md) 记录；课程/参考引擎覆盖的内容不自动全部成为基础综合训练场 V1 的要求。

[Ubisoft 官方求职建议](https://www.ubisoft.com/en-us/studio/annecy/news/7ikcras2odUQqzwc9oVKMY/starting-your-career-in-the-video-game-industry-8-mistakes-to-avoid-easily-when-applying)强调作品展示的质量、可访问性与目标岗位匹配。本页的具体功能取舍是对本项目的建议，不是该文规定的面试门槛；招聘结果也不由某张功能清单保证。现有 C# 引擎路线不变，后续根据实际投递岗位的语言/引擎要求选择展示材料或补充练习，不在此扩张项目范围。

具体契约、精确依赖/静态准备、素材清单和连续开发安排已在实施方案与准备清单保存；范围、Deferred/Undo、M1合并与D53的Ultra分工不再重问。新增API调用、部署/转换及功能验证属于获准后的工作。当前等待最终开工范围弹窗明确同意，没有新增截止日期；后续版本数量/编号不阻塞V1。
