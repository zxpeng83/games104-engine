# 资产与场景：实现深度与数据边界讨论

更新：2026-10-03。状态：**三项方向已获用户明确确认；数据契约、库与分期仍待细化，未实现**。

后续已收敛V1场景层级：用户选择受控父子变换/挂接/保存及Undo；单层模板与场景树是不同职责。GUID/ParentId/LocalTRS、循环检查、保持世界姿态的重挂接、子树事务及缩放/物理限制已在 [实施草案9.1](v1-implementation-draft.md)明确，尚未编码。

本页细化 [总体覆盖表](../plan.md) 中的资产与场景部分，连接已选的 [渲染能力](rendering-roadmap.md)、后续角色/动画与窗口内工具。已确认的场景资源作用域和“新场景准备成功后才替换旧场景”继续适用；本页不重新选择这些事项，也不授权代码实现、安装、配置或 Git 操作。

## 1. 已确认的选择

| 议题 | 助手推荐 | 另一选项 | 当前状态 |
| --- | --- | --- | --- |
| 模型输入 | glTF 2.0/GLB 优先；FBX 经外部工具转换 | 基础版优先直接支持 FBX 工作流 | 路线已选；解析后续选 SharpGLTF.Core，外部转换工具另按需确认 |
| 保存范围 | 先保存设计场景，运行存档另设阶段 | 基础版同时保存一组限定运行状态 | 用户选择先保存设计场景 |
| 模板深度 | 单层对象模板与明确的实例覆盖 | 先场景实例/共享资产引用，模板随后加入 | 用户选择有限模板方案；覆盖契约待细化 |

以上来自用户三项明确答复。格式选择不等于已选定解析库、支持所有扩展或立即建立导入工程；原建议中未涉及选择的具体算法、数据字段和流程仍需审阅。

## 2. 要完成的闭环与三层数据

候选目标是：**少量真实模型/贴图进入引擎 → 资产描述与引用 → 创建场景实例 → 编辑设计参数 → 保存并安全重载 → 运行行为与画面可复现。** 这比“读到一个模型”更完整，但不要求先复制完整 Unity 资产数据库或 Prefab 系统。

| 层次 | 内容 | 边界 |
| --- | --- | --- |
| 源/交换文件 | DCC 导出的模型、图片、骨架与动画数据 | 格式数据不包含本工程全部 Gameplay 规则；DCC 工程与运行资源也不是同一概念 |
| 引擎资产描述 | 来源、导入约定、材质与资源引用、对象模板等 | 描述“这类对象由什么组成”，不保存某个活跃实例的物理接触或 GPU 句柄 |
| 场景设计与运行对象 | 设计文件记录实例摆放和参数；运行时据此构造对象、组件与系统登记 | 实例可以共享资产；运行状态不应通过任意内存序列化悄悄覆盖设计文件 |

glTF 本身可以包含节点和场景，仍不等于本工程的 Gameplay 场景协议；也不必把所有顶点、贴图重写为 JSON。初期可以解析交换文件成为 CPU 资产，再创建本引擎的运行对象和 GPU 表示；自定义二进制 Cook/打包流程留作后续讨论。

## 3. 已选输入格式与待细化的导入边界

- 已选主要输入为 glTF 2.0/GLB；建议先以少量 GLB 验证，再分静态网格/材质、骨架/动画两步支持。具体子集与顺序待定；GLB 是同一格式的二进制封装，不是另一套动画系统。
- glTF 能描述 PBR 材质和蒙皮/关键帧数据，但格式支持不代表本引擎已实现对应着色、动画求值或所有扩展。必须列出实际支持子集，并对不支持内容作明确处理。
- glTF 为右手、Y-up、米制，但资产正面朝 +Z；项目已选默认局部前方 -Z/右方 +X。因此仍需明确模型朝向校正入口，不能因为上轴相同就直接假定兼容。转换要覆盖节点、网格、法线/切线、骨架、绑定关系及动画，不让控制器和 Shader 各补一次修正。
- `.gltf` 的外部缓冲和图片引用、GLB 中是否仍有外部依赖、模型内资源引用，都应由支持范围说明；不把一种扩展名当作“肯定单文件、自包含”的保证。
- 图像/模型解析已选并由用户安装 StbImageSharp/SharpGLTF.Core，包与Debug输出已核对；资产识别、引用、导入约定、运行时构造和生命周期由项目实现。具体版本与素材见 [准备清单](v1-dependencies-and-assets.md)，实际导入验证尚未开始，本轮不转换或复制素材。

格式依据：[Khronos glTF 2.0 规范](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html)、[坐标与单位条款源码](https://github.com/KhronosGroup/glTF/blob/main/specification/2.0/Specification.adoc#coordinate-system-and-units)。规范用于确认数据语义，真正实现时再固定所采用的解析库版本和输入资产。

## 4. 设计场景、模板和运行状态

设计场景保存与单层模板方向已确认；以下具体数据组织、编辑与覆盖语义是该方向的建议细化，仍需形成接口契约。

- 继续使用已选的 System.Text.Json 处理引擎描述数据，设计面向文件的数据类型和可保存字段；不直接序列化整套 Runtime 类型。序列化库能读写字段，不会替我们定义资产依赖、对象身份或资源生命周期。
- 设计场景保存初始摆放、组件配置、资源引用和场景设置；运行时的移动结果、动画游标、物理接触、输入队列和显示历史分别有自己的职责，不默认写回场景。
- 窗口内工具需要区分“修改设计并保存”和“运行期调试”。编辑命令更新设计数据并按安全入口影响预览，普通 Gameplay 更新不反向污染设计源数据；不因此要求创建独立编辑器程序集。
- 单层模板候选：定义默认模型、材质和组件配置，实例保存自身摆放及有限覆盖。覆盖哪些字段、模板更新何时生效、实例如何恢复默认都需明确；不自动承诺嵌套、变体继承链、任意组件增删覆盖和完整 Apply/Revert。
- 共享模板与实例的修改必须可辨认：修改某个实例允许覆盖的颜色，不应意外修改全部使用者；修改共享定义则应按约定影响使用者并在工具中提示作用范围。
- 导入模型节点层级、骨骼层级与本工程场景对象父子关系需分别描述。场景层级的首版范围、变换继承及物理对象限制尚未确认，不能从模型含节点就推断已具备完整场景编辑层级。

JSON 参考：[System.Text.Json 支持的数据类型](https://learn.microsoft.com/en-us/dotnet/standard/serialization/system-text-json/supported-types)。只使用与当前 .NET 10 基线相符的能力，不因文档同时介绍后续版本就升级 SDK 或包。

## 5. 身份与引用：必须区分、具体方案待定

| 身份 | 要回答的问题 | 不可混淆 |
| --- | --- | --- |
| 资产身份 | 引用的是哪一份共享模型/材质/模板？ | 同一模型的三个箱子可以使用同一资产身份 |
| 场景对象身份 | 场景中是哪一次摆放，机关引用哪一个目标？ | 三个实例必须可区分；需要跨保存重载的关系不能只依赖临时内存地址或不稳定遍历顺序 |
| 运行句柄 | 当前会话中的物理对象、GPU 资源或临时查询对象是哪一个？ | 不能把 GPU 整数句柄直接当成持久资产或场景 ID |

项目相对路径最容易检查，但移动/重命名会影响引用；包装成 AssetKey 不会自动解决这一点。稳定 GUID/逻辑 ID 可分离身份与位置，但需要索引、唯一性检查和移动/复制规则。这项选择尚未进行，不提前建立完整资产数据库，也不把 Piccolo 的运行期整数映射视为持久 GUID 方案。

加载还包括解析结构、解析依赖、检查引用和建立运行对象，不能只以 JSON 解析成功判定整个场景成功。缺失或错误引用要能定位来源，具体错误与兼容契约在对应实施计划中确定。

## 6. 候选分块与验收

A 编号只表示该模块内部讨论顺序，不是完整工程排期，也不是要求基础绘制实现所有资产能力。

| 讨论块 | 候选内容 | 可见验收与协作 |
| --- | --- | --- |
| A1 描述与引用 | 引擎资产描述、场景设计数据、可保存字段、基本版本和依赖错误 | 能读懂文件含义；缺失资源或错误组件可定位；尚不创建万能迁移框架 |
| A2 静态资产入口 | 根据选定格式读取一个真实模型和贴图，适配位置/法线/材质与颜色契约 | 模型朝向、尺寸、法线和材质正确；与渲染 R2/R3 协作 |
| A3 场景实例与模板 | 多实例共享资产、独立摆放与覆盖；明确对象身份及引用 | 三个实例不重复复制几何，修改一个实例不误改其他实例；具体模板机制以选择为准 |
| A4 编辑保存与重载 | 保存设计数据、重新构造场景；继续采用新场景成功后替换旧场景 | 保存/重载恢复约定设计字段；运行暂态按保存契约处理；失败保留旧场景 |
| A5 骨架与动画输入 | 按动画阶段需要读取节点、Skin、绑定与 Clip 数据 | 绑定姿态正确，已知关键帧可追踪；导入成功不等于动画求值/混合已经实现 |
| A6 后续工具链专题 | 稳定资产身份、依赖分析、版本迁移、重导入、异步加载/Cook/打包、模板扩展等按目标分期 | 每项选可运行实验并定义收益和边界，不因目录或函数存在宣称完整流水线 |

基础候选验收还包括：保存失败不破坏原设计文件；重复加载资源登记数量稳定；模板/材质共享边界可解释；加载失败清理本次部分创建资源；窗口内设计编辑与运行调试不会无意相互覆盖。

测试对象应覆盖实际持久字段，而不是只证明“保存出来的 JSON 还能解析”。例如场景设置和角色引用若被列入契约，也要进入往返验证。帧循环、物理/动画暂态、工具选中状态和 GPU 句柄不能未经设计一起写入文件。
