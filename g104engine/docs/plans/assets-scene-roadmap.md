# 资产与场景：实现深度与数据边界讨论

本页维护资产/场景已选路线、数据边界与长期实践。V1有限范围见[v1-baseline.md](v1-baseline.md#scope)，Cook、资产数据库、模板扩展与运行存档不由路线自动获准。

可选现行说明：[scene-and-editor.md](../guides/scene-and-editor.md)、[rendering-and-animation.md](../guides/rendering-and-animation.md)；来源/部署见[dependencies.md](../guides/dependencies.md)。本页不承担实际进度台账。

本页细化[plan.md](../plan.md#roadmap)，保留起步选择与长期路线。设计闭环依赖资源作用域和准备成功才提交；导入、编辑、动画与渲染应按依赖协作。

<a id="choices"></a>
## 1. 已确认的选择

| 议题 | 助手推荐 | 另一选项 | 确认结论 |
| --- | --- | --- | --- |
| 模型输入 | glTF2.0/GLB优先；FBX经外部工具转换 | 基础版优先直接支持FBX工作流 | 用户选择glTF/GLB受控子集；FBX工作流另定 |
| 保存范围 | 先保存设计场景，运行存档另设阶段 | 基础版同时保存一组限定运行状态 | 用户选择先保存设计场景 |
| 模板深度 | 单层对象模板与明确实例覆盖 | 先场景实例/共享资产引用，模板随后加入 | 用户选择单层模板；嵌套/变体/完整Apply-Revert后续 |

以上保留最初三项选择；格式解析库与有限支持不能代替引擎自己的引用、实例和资源寿命设计，也不代表完整导入工具链。

<a id="data-layers"></a>
## 2. 要完成的闭环与三层数据

目标闭环是：**真实模型/贴图→资产引用→场景实例→编辑设计参数→保存并安全重载→运行行为与画面。** 有限闭环不等于Unity资产数据库或完整Prefab系统。

| 层次 | 内容 | 边界 |
| --- | --- | --- |
| 源/交换文件 | DCC 导出的模型、图片、骨架与动画数据 | 格式数据不包含本工程全部 Gameplay 规则；DCC 工程与运行资源也不是同一概念 |
| 引擎资产描述 | 来源、导入约定、材质与资源引用、对象模板等 | 描述“这类对象由什么组成”，不保存某个活跃实例的物理接触或 GPU 句柄 |
| 场景设计与运行对象 | 设计文件记录实例摆放和参数；运行时据此构造对象、组件与系统登记 | 实例可以共享资产；运行状态不应通过任意内存序列化悄悄覆盖设计文件 |

glTF 本身可以包含节点和场景，仍不等于本工程的 Gameplay 场景协议；也不必把所有顶点、贴图重写为 JSON。初期可以解析交换文件成为 CPU 资产，再创建本引擎的运行对象和 GPU 表示；自定义二进制 Cook/打包流程留作后续讨论。

<a id="input"></a>
## 3. 输入选择与扩展边界

- V1输入选择未压缩glTF2.0/GLB三角形、受控材质/UV0、节点skin/TRS与STEP/LINEAR，PNG/JPEG解码。扩展CUBICSPLINE、Morph、压缩/扩展必须另定义支持和拒绝规则。
- glTF 能描述 PBR 材质和蒙皮/关键帧数据，但格式支持不代表本引擎已实现对应着色、动画求值或所有扩展。必须列出实际支持子集，并对不支持内容作明确处理。
- glTF右手/Y-up/米制且资产正面朝+Z，项目默认前-Z/右+X。在角色实例边界统一校正朝向/高度/feet并保留模型根变换；mesh/skin空间链分别说明，控制器与Shader不能各补一次。
- `.gltf` 的外部缓冲和图片引用、GLB 中是否仍有外部依赖、模型内资源引用，都应由支持范围说明；不把一种扩展名当作“肯定单文件、自包含”的保证。
- 图像/格式库负责解码，项目负责引用/实例/生命周期及空间适配。具体锁定版本与采用素材集中在依赖指南；更换库或输入须重新评估兼容和回归成本。

格式依据：[Khronos glTF 2.0 规范](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html)、[Specification.adoc](https://github.com/KhronosGroup/glTF/blob/main/specification/2.0/Specification.adoc#coordinate-system-and-units)。规范用于确认数据语义，真正实现时再固定所采用的解析库版本和输入资产。

<a id="save"></a>
## 4. 设计场景、模板和运行状态

设计场景与模板按V1选定边界起步；字段/操作的低级合同在场景/编辑指南，以下说明职责与扩展要求。

- 继续使用已选的 System.Text.Json 处理引擎描述数据，设计面向文件的数据类型和可保存字段；不直接序列化整套 Runtime 类型。序列化库能读写字段，不会替我们定义资产依赖、对象身份或资源生命周期。
- 设计场景保存初始摆放、组件配置、资源引用和场景设置；运行时的移动结果、动画游标、物理接触、输入队列和显示历史分别有自己的职责，不默认写回场景。
- 窗口内工具需要区分“修改设计并保存”和“运行期调试”。编辑命令更新设计数据并按安全入口影响预览，普通 Gameplay 更新不反向污染设计源数据；不因此要求创建独立编辑器程序集。
- 单层模板实例保持独立GUID与完整有效字段，覆盖字段须明确；V1不自动传播所有默认值变化、不含嵌套/变体/Apply-Revert。父子层级独立于模板深度。
- 共享模板与实例的修改必须可辨认：修改某个实例允许覆盖的颜色，不应意外修改全部使用者；修改共享定义则应按约定影响使用者并在工具中提示作用范围。
- 受控场景父子、物理根节点及父缩放规则见V1基线；当前可编辑组件边界不能由纸面根节点原则推为任意组件编辑。模型/skin骨骼树独立求值，不是可任意删改的场景骨骼对象。

JSON 参考：[System.Text.Json 支持的数据类型](https://learn.microsoft.com/en-us/dotnet/standard/serialization/system-text-json/supported-types)。只使用与当前 .NET 10 基线相符的能力，不因文档同时介绍后续版本就升级 SDK 或包。

<a id="identity"></a>
## 5. 身份与引用的选择

| 身份 | 要回答的问题 | 不可混淆 |
| --- | --- | --- |
| 资产身份 | 引用的是哪一份共享模型/材质/模板？ | 同一模型的三个箱子可以使用同一资产身份 |
| 场景对象身份 | 场景中是哪一次摆放，机关引用哪一个目标？ | 三个实例必须可区分；需要跨保存重载的关系不能只依赖临时内存地址或不稳定遍历顺序 |
| 运行句柄 | 当前会话中的物理对象、GPU 资源或临时查询对象是哪一个？ | 不能把 GPU 整数句柄直接当成持久资产或场景 ID |

V1选择根目录内规范化相对路径作资产引用，GUID作持久场景身份，设备/后端句柄不落盘。路径越界、重复身份、缺失父引用均须校验；路径引用仍受重命名/移动影响，完整资产GUID数据库另做专题。

加载须完成描述/版本/字段/引用检查及真实资源准备后提交；损坏设计保留原件并可定位诊断，保存/编辑/Undo失败保护原状态。不能只以JSON能解析判断整个场景成功。

<a id="practice"></a>
## 6. 基础闭环与后续分块

A编号保留模块讨论顺序，不是统一排期。A1–A5给出基础闭环与学习验收方向，A6为未来工具链候选；所有失败分支与格式覆盖仍须实际验证。

| 讨论块 | 基础能力 / 后续候选 | 验收与学习方向 |
| --- | --- | --- |
| A1 描述与引用 | 引擎资产描述、场景设计数据、可保存字段、基本版本和依赖错误 | 能读懂文件含义；缺失资源或错误组件可定位；尚不创建万能迁移框架 |
| A2 静态资产入口 | 根据选定格式读取一个真实模型和贴图，适配位置/法线/材质与颜色契约 | 模型朝向、尺寸、法线和材质正确；与渲染 R2/R3 协作 |
| A3 场景实例与模板 | 多实例共享资产、独立摆放与覆盖；明确对象身份及引用 | 三个实例不重复复制几何，修改一个实例不误改其他实例；具体模板机制以选择为准 |
| A4 编辑保存与重载 | 保存设计数据、重新构造场景；继续采用新场景成功后替换旧场景 | 保存/重载恢复约定设计字段；运行暂态按保存契约处理；失败保留旧场景 |
| A5 骨架与动画输入 | 按动画阶段需要读取节点、Skin、绑定与 Clip 数据 | 绑定姿态正确，已知关键帧可追踪；导入成功不等于动画求值/混合已经实现 |
| A6 后续工具链专题 | 稳定资产身份、依赖分析、版本迁移、重导入、异步加载/Cook/打包、模板扩展等按目标分期 | 每项选可运行实验并定义收益和边界，不因目录或函数存在宣称完整流水线 |

基础候选验收还包括：保存失败不破坏原设计文件；重复加载资源登记数量稳定；模板/材质共享边界可解释；加载失败清理本次部分创建资源；窗口内设计编辑与运行调试不会无意相互覆盖。

测试对象应覆盖实际持久字段，而不是只证明“保存出来的 JSON 还能解析”。例如场景设置和角色引用若被列入契约，也要进入往返验证。帧循环、物理/动画暂态、工具选中状态和 GPU 句柄不能未经设计一起写入文件。
